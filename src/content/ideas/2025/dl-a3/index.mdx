## Sequence Modeling Exposes the Bottleneck

Sequence modeling makes the limitations of fixed-size summaries clear. In translation, the model has to read one sequence, generate another, preserve meaning, handle order, and make coherent decisions one token at a time.

The assignment walks through that progression with an LSTM, a seq2seq model with attention, and transformer-based variants. Each architecture addresses a different bottleneck.

> [!note]
> The assignment appears here only as context. The goal of this post is to explain the concepts that matter without publishing restricted implementation details.

## Project Scope

The project moved through three stages:

1. understand recurrence and gating well enough to build an LSTM,
2. move from encoder-decoder bottlenecks to attention,
3. compare recurrent models against transformer-style sequence processing.

The assignment is a compact map of modern NLP architecture history. The same question runs through all three stages: how does the model preserve, retrieve, and use information from earlier in the sequence?

The repo made the comparison explicit. It included separate training paths, saved best configurations, side-by-side model comparison scripts, and direct inspection of translated outputs under matched evaluation settings.

## Translation Is Conditional Sequence Modeling

A translation model does not predict one label. It predicts a target sequence conditioned on a source sequence:

$$
p_{\theta}(y \mid x)=\prod_{t=1}^{T}p_{\theta}(y_t \mid y_{<t},x).
$$

That factorization immediately creates several difficulties:

- the output length is not fixed,
- each new token depends on earlier output choices,
- and mistakes can compound over time.

Those constraints, not just a bigger dataset, are why sequence modeling needs its own architectures and evaluation methods.

## Seq2Seq Models Expose the Bottleneck Problem

Classic encoder-decoder models compress the source sequence into hidden states and then decode from that representation. The structure is straightforward: one network reads, another writes. The limitation appears once sentences get longer or more structurally complex.

The bottleneck framing predicts the failure modes you see:

- omitted content,
- repetitions,
- weak alignment between source and output,
- and degraded performance on longer sequences.

The seq2seq stage matters because it makes the architectural limitation feel like a direct consequence of the setup.

## Attention as Retrieval

Attention lets each decode step retrieve the most relevant source-side information dynamically, with access to source states throughout decoding.

<Figure
  src={p3Fig2}
  alt="Attention map"
  caption="Attention can be understood as dynamic retrieval over token states within the network. Source: Lowyx GT DL Notes (CC BY 4.0), https://lowyx.com/posts/gt-dl-notes/."
  width={900}
/>

In its standard form,

$$
\mathrm{Attention}(Q, K, V) = \mathrm{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V.
$$

The softmax weights determine which positions matter for the current decision. That changes the character of the model. Alignment is no longer implicit and fragile; the network can compute it step by step.

At that point, sequence modeling looks more like information routing than memory compression.

**Illustrative toy snippet, not assignment code:**

```python
import torch

def scaled_dot_product_attention(q, k, v, mask=None):
    scores = (q @ k.transpose(-2, -1)) / (q.size(-1) ** 0.5)
    if mask is not None:
        scores = scores.masked_fill(~mask, float("-inf"))
    weights = scores.softmax(dim=-1)
    return weights @ v
```

The important part is the structure: compare keys against the current query, suppress invalid positions with a mask when needed, and turn those scores into a weighted retrieval step.

## Transformers Reorganize the Computation

Transformers push the idea further by making attention, residual paths, layer normalization, and feed-forward blocks the dominant computation pattern.

<Figure
  src={p3Fig3}
  alt="Multi-head attention"
  caption="Multi-head attention matters because one relation type is rarely enough; the model benefits from attending in several subspaces at once. Source: Lowyx GT DL Notes (CC BY 4.0), https://lowyx.com/posts/gt-dl-notes/."
  width={900}
/>

The main consequences are:

- recurrence is no longer the main path for combining information,
- many dependencies can be modeled in parallel during training,
- and positional information has to be injected explicitly because attention alone is permutation-invariant.

Attention gets the spotlight, but positional encodings and residual structure are a big part of why transformers work as well as they do.

The assignment clarifies this by comparing recurrent and transformer-style models on roughly the same task. The newer family also gives a different answer to "where should relevant information come from at each step?"

## Decoding Belongs to the System

Even with a trained sequence model, inference policy still matters. Greedy decoding, beam search, and sampling can produce materially different behavior from the same learned distribution.

<Figure
  src={p3Fig4}
  alt="Beam search"
  caption="Decoding policy is part of model behavior because it changes the search process used to turn probabilities into actual sequences. Source: Lowyx GT DL Notes (CC BY 4.0), https://lowyx.com/posts/gt-dl-notes/."
  width={900}
/>

Translation quality is a model-plus-decoder property. If two systems are compared with different inference policies, it becomes harder to tell whether the gain came from better learned representations or from a different search strategy.

In the project, sequence evaluation was inseparable from inference design.

**Illustrative toy snippet, not assignment code:**

```python
# greedy decoding
tokens = [bos_id]
for _ in range(max_steps):
    next_id = model(tokens)[-1].argmax().item()
    tokens.append(next_id)

# beam search keeps several partial sequences alive
beams = [([bos_id], 0.0)]
for _ in range(max_steps):
    candidates = []
    for seq, score in beams:
        log_probs = model(seq)[-1].log_softmax(dim=-1)
        top_scores, top_ids = log_probs.topk(beam_width)
        for s, idx in zip(top_scores.tolist(), top_ids.tolist()):
            candidates.append((seq + [idx], score + s))
    beams = sorted(candidates, key=lambda x: x[1], reverse=True)[:beam_width]
```

The contrast makes decoding policy visible: one path commits immediately, while the other keeps several plausible continuations alive and scores them jointly.

## Metrics Need Error Analysis

Perplexity and BLEU are informative, but they compress too much. Translation errors are structurally different from one another. A model can get the broad meaning right while damaging word order, or preserve fluency while dropping a content word that matters.

<Figure
  src={p3Fig5}
  alt="Alignment and translation errors"
  caption="Alignment views help because they make omission and reordering errors more visible than a scalar metric can. Source: Lowyx GT DL Notes (CC BY 4.0), https://lowyx.com/posts/gt-dl-notes/."
  width={900}
/>

The assignment showed that error taxonomies are more actionable than a single score. Once you separate lexical substitution, reordering, omission, and repetition, it becomes easier to decide whether the next intervention should be architectural, optimization-related, or decoder-related.

The repo reflected that too. There were separate scripts for reporting perplexity and comparing model outputs, because scalar metrics tell you that a difference exists, while output inspection starts to show what kind of difference it is.

## Recap

The main sequence-modeling ideas from this project:

- Bottlenecks come from model structure, and they show up in both training and evaluation.
- Attention is a retrieval mechanism built into the computation.
- Transformers solve several problems at once: dependency modeling, training parallelism, and representational flexibility.
- Decoding and evaluation policies shape what "good performance" even means.

Working through the older bottlenecks first is what makes the move from RNNs to attention to transformers feel earned rather than handed to you.
